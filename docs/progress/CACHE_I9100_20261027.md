# I9100 cache/performance correction — 2026-10-27

The user confirms that touch now works, but boot still takes about 10 minutes and the UI advances roughly once per 30 seconds after the previous performance build. That result supersedes any expectation of a performance improvement in PERFORMANCE_I9100_20261027.md. No hardware result for this new build is available yet.

## Established source defects

The final bootstrap direct-RAM mapping used `MMU_TEXCB_CA_WT_NWA << 2`: the constant is 2, so the descriptor gets 0x008, which encodes Device memory rather than Normal write-through. The normal pmap default used 0x188: inner Write-Through, outer Write-Back/Write-Allocate. ARM explicitly states that Cortex-A9 treats Write-Through pages as non-cacheable even with SCTLR.C set. These are concrete mapping defects and a plausible common cause of slow kernel work and software rendering; the amount of hardware improvement is unmeasured.

Primary reference: [ARM Cortex-A9 TRM](https://documentation-service.arm.com/static/5e7e23ffb471823cb9de5920), sections 3.4 (PIPT data / VIPT instruction cache), 6.3 and 7.4.3 (WT behavior). Descriptor fields use the ARMv7 short-descriptor encoding with TEX remapping disabled.

## Changes

- I9100 RAM now uses Normal, non-shareable, inner/outer WBWA (small-page cache bits 0x04c). `locore.s` clears SCTLR.TRE before enabling the MMU; inherited PRRR/NMRR values cannot reinterpret the policy. The early boot section tables are replaced while D-cache is still disabled.
- Framebuffer identity sections, the direct RAM alias and later IOKit aliases all use Normal NC (small-page bits 0x040, section TEX bits 0x1000). The entire two-section scanout aperture is excluded from the free-page allocator and managed-page classification, with matching free-page accounting. Previously those pages could be handed to VM while FIMD was using them.
- Hardware registers remain strongly ordered/uncached. CPU1, ACTLR.SMP, clocks and the external PL310 setup are unchanged.
- Cache mode reset to zero/default restores WBWA. Explicit cache inhibit, write combine and write-through requests get Normal NC on RAM. Managed aliases and the untracked bootstrap direct mapping change together, after draining cached page data, using descriptor break/clean/DSB/TLBI/make/clean/DSB/TLBI. No-op transitions avoid unnecessary work. `pmap_cache_attributes` now tests the cache bit with correct operator precedence on I9100.
- Live PTE changes clean the descriptor and execute DSB before TLB invalidation. New zeroed L2 tables and copied/expanded L1 tables are cleaned before publication. Kernel text/data protection, remove and page-protect paths also clean their modified PTEs.
- Initial cache enable discards inherited L1 tags through the L1 set/way helper. Executable-page insertion and protection changes clean D-cache and invalidate all I-cache aliases plus branch predictors, rather than invalidating only a kernel virtual alias of VIPT instructions.
- Fixed a separate pmap initialization allocation error: the PV hash/lock arrays were placed after the older `pv_head_table` allocation, rather than after the newly allocated `pv_head_hash_table` rooted-entry array. I9100 now uses the actual current allocation as its base (as the existing Leo branch already did).
- SD transport/touch behavior is retained. Added cumulative read-path time, bytes, divider and failed-request counts to the SD wrapper. Measurements include PIO and buffer delivery, exclude lock wait, and are wall time rather than isolated CPU time.

## On-device diagnostics

This diagnostic build draws two 16-pixel text rows at the bottom of the lock screen, after each submitted frame. `i9100perf=0` disables the strip. The existing UI surface and touch coordinates are unchanged.

Example labels, not measured results:

```
CACHE2 #... COPY ...us GAP ...ms IRQ ...
SD d... ...KiB ...ms E... C1 RAM04c FB040
```

- `CACHE2` identifies this build. `COPY` measures the full framebuffer copy plus its first DSB, before drawing the strip. `GAP` measures the time between beginnings of successive presents. The first gap/IRQ delta is zero; a later long gap can also reflect a naturally idle screen.
- `IRQ` is the scheduler interrupt delta between present snapshots, not a rate. For an actively animating screen, a large GAP with few IRQs points toward timer/interrupt scheduling; a small COPY with large GAP points upstream of the scanout copy.
- `SD` reports cumulative KiB and milliseconds spent in the read path, followed by failed I/O requests (`E`). `d` is the SDHCI divider field: nominal 50MHz/(2*d), so d2 is about 12.5MHz and d128 about 195kHz. Actual parent-clock frequency has not been measured on this device.
- `C` is SCTLR.C. `RAM` and `FB` are actual cache bits read from the source surface and framebuffer kernel PTEs; expected values are 04c and 040. C=1 alone does not prove that RAM is cacheable.
- For another device test, record cold-boot duration and photograph both rows while the slide animation is active. This separates read-path delays, sparse IRQ delivery, rendering delays and framebuffer copy cost without requiring UART.

The strip writes about 60KiB of pixels per present and is deliberately temporary. COPY excludes that overhead; GAP includes prior strip work and any other elapsed time. Snapshot fields are individual 32-bit values, so SD fields may straddle a concurrent update. They are diagnostics, not synchronized accounting.

## Validation and recovery

`tools/check_i9100_cache.py` compiles actual selected pmap functions with mocked MMU/cache operations under ASan/UBSan. It checks every page in the 1GiB RAM map, MMIO, reserved scanout, TEX/C/B decoding, default/WT/inhibit/reset semantics, three aliases, data drain and break/clean/TLBI/make ordering, and allocator skipping/counting across the framebuffer hole. It does not emulate real caches or interrupt timing.

The existing storage, touch and timing/framebuffer checks pass under their sanitizer harnesses. The RELEASE ARM EXYNOS4210_I9100 kernel and uniLoader are rebuilt and packaged. Logs and hashes are in `diagnostics/cache-20261027/`; the change patch is `cache-i9100-20261027.patch`. Kernel build retains existing toolchain warnings; no runtime speed claim is made.

The prior delivered build, reported to boot with working touch but severe lag, is preserved in `backups/touch-working-cache-before-20261027/`, including archives, images, unstripped kernel, dSYM and source originals. Its checkpoint manifest records the user report. The older boot-only checkpoint in `backups/booted-20261027/` remains untouched.
